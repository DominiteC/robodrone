## 根因分析：为什么高度做不到像 Yaw 那样"打杆动、回中定"

核心问题可以归结为**控制结构的根本差异**——yaw 用的是"角位置指令"模式，高度用的是"速度指令"模式。下面是逐层对比。

---

### 1. 操纵杆 → 目标值的映射方式完全不同

| | Yaw | 高度 |
|---|---|---|
| 摇杆原始值 | 角度量（±150） | 油门 0~100，中位 50 |
| 映射结果 | **角度增量** → 累积进 `Desired_yaw`（位置型） | **爬升速度** `cm/s` → 直接写入 `setpoint->vel.z`（速度型） |
| 杆回中时 | `Desired_yaw` **锁定在当前实测角度**，PID 死守这个角位置 | 高度目标**瞬间快照**当前高度 ± 一个最多 ±10cm 的漂移修正量 |

**Yaw 的杆是"角速度指令"**：在 `control.c` 的 `Yaw_Control()` 中，杆量除以 100 再乘 `YAW_MAX_RATE`（42°/s），每周期积分进 `Desired_yaw`[Yaw_Control](user/control/control.c:162-164)。杆回中时，`Desired_yaw` 被锁到当前实测 `yaw_meas_cont`，然后角位置 PID 守住这个角度[Yaw_Control](user/control/control.c:167-170)。

**高度的杆是"速度指令"**：在 `commander.c` 的 `commanderGetSetpoint()` 中，杆量换算成 `climb`（±50 cm/s），直接赋给 `setpoint->vel.z`[commanderGetSetpoint](user/communicate/commander.c:152)。**杆回中时**，代码把高度目标设为 `state->height + errorPosZ`（`errorPosZ` 是一个最多 ±10cm 的累积漂移修正）[commanderGetSetpoint](user/communicate/commander.c:161-170)。

**这意味着什么？** 杆回中那一瞬间，"拍"了一个高度目标，但这个目标本身就带着 ±10cm 的不确定性。而且之前杆在动的时候，高度目标根本没有被连续更新——它只在回中那一刻算一次。

---

### 2. PID 结构差异：高度环有 I 项，Yaw 没有

| | Yaw 角速度 PID | Z 速度 PID |
|---|---|---|
| Kp | **0.6** | **0.03**（小 20 倍） |
| Ki | **0.0** | **0.01**（有积分！） |
| 积分限幅 | 8 | **1000** |

数据来源：[control.c 第 38-87 行的 PID 初始化配置](user/control/control.c:38-87)。

Z 速度 PID 的 **Kp 只有 0.03**，是 yaw 速率 Kp 的 1/20。因为比例增益太弱，靠积分项 Ki=0.01 来补足——但积分天然会引入**超调和振荡**：误差累积 → 输出过大 → 冲过头 → 反向误差累积 → 又冲过头，反复震荡。

Yaw 速率环 Ki=0，纯靠大 Kp 硬拉住，没有积分导致的过冲。

---

### 3. 高度位置 PID 的 DeadBand 是 0

[高度位置 PID 的 DeadBand = 0](user/control/control.c:75)，意味着**任何微小的高度误差都会产生修正输出**——传感器噪声、气流扰动都会触发 PID 响应。而 yaw 角位置 PID 的 DeadBand = 0.1°，给了系统一个容忍带。

---

### 4. 高度位置 PID 输出被两次钳位

高度位置 PID 输出（期望爬升速度）先经过 PID 自身的 MaxOut=80，又被硬钳到 **±20 cm/s**：

```
target->vel.z = fmaxf(-20.f, fminf(20.f, pid_height_position.Output));
```

[control.c 第 252 行](user/control/control.c:252)。

这意味着位置环的"嗓门"被压得很小——它只能命令一个最高 20cm/s 的速度去追高度误差。当杆回中后，如果"快照"的高度目标不准，位置环需要较长时间才能追上，这期间速度环的积分在持续累积/反向累积，造成来回晃。

---

### 5. 高度多了一个输出平滑滤波器

[control.c 第 271 行](user/control/control.c:271) 有一个 `thrustLpf`，用 0.003 的时间常数对最终油门输出做低通滤波。Yaw 没有对应的后置滤波。这个滤波引入了额外的相位滞后，进一步恶化稳定性。

---

## 一句话总结

> **Yaw 是"杆偏多少角度 → 积分到目标角 → 位置 PID 死守"**，杆回中时目标角锁定、积分清零、比例增益够大。
>
> **高度是"杆偏多少 → 直接当速度目标 → 两个串级 PID 追"**，杆回中时高度目标只快照一次、位置环 DeadBand=0 对噪声也响应、速度环 Kp 太小靠积分硬扛导致过冲来回晃。

要让高度做到和 yaw 一样的"打杆动、回中定"，需要在控制结构上对齐——比如把油门杆也映射为**高度变化率**并连续积分进高度目标（像 yaw 积分出 `Desired_yaw` 一样），同时给位置环加 DeadBand、去掉或大幅减小速度环积分、提高速度环比例增益。

Now I understand the MiniFly PWM output chain:

1. `velocityController()` produces `thrust` in range 1000-60000
2. `powerControl()` takes `control->thrust` and distributes to 4 motors with standard X-quad mixing
3. `limitThrust()` clamps motor values to 0-65535 (uint16)
4. `motorsSetRatio()` takes the 0-65535 value, does battery compensation, and sets TIM CCRx

So in MiniFly, the thrust is in the same "units" as the motor PWM (0-65535 range). The hover throttle is around 20000 (THRUST_BASE macro), which is about 30% throttle.

5. **The mode switch approach works around sensor limitations**: During velocity mode, the drone follows a velocity command using the (imperfect) velocity estimate. When the stick is released, it snaps to the current height estimate as a position target. The position hold then uses the barometer as an absolute reference. This avoids the problem of integrating noise over long periods.

There's also a user experience consideration: For yaw, integrating stick rate to angle feels natural — you're pointing the drone in a direction. For height, people typically think in terms of "go up/down at a certain speed" rather than "go to a specific height." The velocity-mode approach matches the user's mental model better: push stick → drone climbs at proportional speed, release → drone holds.

1. No clean vertical velocity sensor equivalent to a gyro
2. Noisy/drifty absolute height reference
3. Velocity control is a pragmatic workaround for these sensor limitations

## 问题一：快照时的 `errorPosZ` 哪来的？干嘛的？

### 来源追踪

`errorPosZ` 是一个 **static 变量**，初始值为 0。它的生命周期贯穿整个飞行过程：

```
阶段1：位置保持（杆在死区）
┌─────────────────────────────────────────────────────┐
│ 每周期执行：                                         │
│   errorPosZ = setpoint->position.z - state->position.z │
│   errorPosZ = constrainf(errorPosZ, -10.f, 10.f)      │
│                                                     │
│ 含义：持续追踪"设定高度 - 实际高度"的差值               │
│ 如果气压计漂了3cm，errorPosZ 就会稳定在 ≈ 3            │
└─────────────────────────────────────────────────────┘
         ↓ 用户打杆，isAdjustingPosZ = true
         
阶段2：速度模式（杆偏）
┌─────────────────────────────────────────────────────┐
│ errorPosZ 冻结 —— 不再更新                            │
│ 保留着阶段1最后的稳态误差值                             │
└─────────────────────────────────────────────────────┘
         ↓ 用户回中杆，isAdjustingPosZ 从 true 变 false
         
阶段3：快照瞬间（就是你说的这行代码）
┌─────────────────────────────────────────────────────┐
│ setpoint->position.z = state->position.z + errorPosZ │
│                                                     │
│ 用冻结的 errorPosZ 去补偿高度估计的系统偏差             │
└─────────────────────────────────────────────────────┘
```

### 它干嘛的？

**它是"漂移补偿记忆"**。气压计高度存在缓慢漂移——温度变化、气压变化都会导致 `state->position.z` 在飞机物理位置不动的情况下缓慢偏移。在位置保持阶段，`errorPosZ` 每一周期都在学习这个漂移量。当用户打完杆回中时，如果不加这个补偿，直接 `setpoint->position.z = state->position.z` 会把漂移量也"吃进去"——本来飞机没动，但因为气压计漂了 5cm，快照的目标就偏了 5cm。加上冻结的 `errorPosZ` 相当于把之前学到的修正量带过来。

但说实话，**这个补偿的作用有限且不是关键**。第一次起飞时 `errorPosZ = 0`（因为 `initHigh = false` 时被清零），第一次快照就是纯 `state->position.z + 0`。它只是一个辅助性的漂移修正，并不是 MiniFly 不晃的主要原因。

## 问题二：为什么高度不能像 Yaw 一样写？

这是核心问题。Yaw 能做到"杆即速率、积分得位置、杆回中即锁定"，但高度不行——**有物理上的根本限制**。

### Yaw 为什么能这样写

```
摇杆 → 角速率指令 → 积分 → 目标角度 → 角位置PID → 角速率PID → 电机
                         ↑
                    陀螺仪直出角速率（干净！）
```

陀螺仪（MEMS gyro）直接测量角速率——这是它的原生物理量。信号链路极短：**角速率 → 积分 → 角度**。陀螺仪数据干净、低噪声、零漂在短时间内可忽略（积分几秒到几分钟不会明显发散）。

### 高度为什么不能照搬

```
摇杆 → 高度速率指令 → 积分 → 目标高度 → 位置PID → 速度PID → 电机
                          ↑
                     ⚠ 没有传感器能直接测垂直速度！
```

高度方向**没有一个"垂直陀螺仪"**。你能用的传感器：

| 传感器 | 能测什么 | 问题 |
|---|---|---|
| **气压计** | 绝对高度（间接） | 慢、噪声 ±10~30cm、温漂 |
| 气压计微分 | 垂直速度 | 极噪，需要大量滤波 → 滞后 |
| **加速度计 Z** | 比力（含重力） | 积分得速度，重力扣除误差 → 秒级发散 |
| **超声波/激光** | 相对地面高度 | 只有低空（<2~4m）有效 |

MiniFly 的垂直速度 `state->velocity.z` 是通过"气压计微分 + 加速度计融合 + 低通滤波"估算出来的，和陀螺仪直出的角速率完全不是一个质量等级。

### 如果硬要写成像 Yaw 一样会怎样？

假设你把油门杆映射为"期望高度变化率"，每周期积分进高度目标：

```c
Desired_height += stick * MAX_CLIMB_RATE * dt;  // 模仿 yaw 的积分方式
```

问题来了：**杆回中后，`stick = 0`，`Desired_height` 确实锁定了。但你的高度测量在漂！**

- 气压计飘了 5cm → 位置 PID 看到 5cm 误差 → 推油门修正 → 飞机实际动了 → 气压计又飘回来 → PID 反向修正 → 来回晃
- 而且积分出的 `Desired_height` 是一个**绝对数值**（比如 123.7cm），但你的高度传感器本身就不是绝对准确的——气压计在飞行过程中因为桨叶气流扰动（"锅底效应"）会有几厘米的跳动，这个跳动直接变成位置误差驱动 PID 乱调

**Yaw 不存在这个问题**，因为陀螺仪积分出来的角度在分钟级尺度上不会漂，而且没有外部扰动会让陀螺仪"觉得"角度变了但实际没变。

### MiniFly 采用"速度模式 + 回中快照"的本质原因

```
       ┌─ 杆偏：速度直给 ─────────────────────┐
       │  不需要绝对高度参考                     │
       │  只需要速度估计（传感器融合可接受）        │
       │  避免了"积分噪声"                        │
       └──────────────────────────────────────┘
                     ↓ 杆回中
       ┌─ 快照当前高度为位置目标 ───────────────┐
       │  利用气压计"此刻"的绝对高度               │
       │  虽然气压计有绝对偏差，但短时稳定性还行      │
       │  位置环 D 项提供阻尼防止过冲               │
       └──────────────────────────────────────┘
```

这是一种务实的妥协：
- **速度模式**不需要绝对高度准，只需要相对变化感知 → 避开了气压计绝对精度差的问题
- **回中快照**把气压计此刻的值"冻结"为目标 → 避开了连续积分导致的漂移累积
- 代价就是模式切换时有轻微冲击 → 用位置环的 D 项阻尼来消化

### 一句话总结

> Yaw 能积分是因为 **陀螺仪直出角速率，既干净又不漂**。高度没有这样的传感器——垂直速度是融合估算出来的，绝对高度也漂。如果像 yaw 一样积分高度，传感器噪声和漂移会在积分过程中不断累积，结果就是目标高度自己都不知道自己飞哪去了。MiniFly 的"速度模式 + 快照"方案是用模式切换来隔离传感器漂移——速度阶段不需要绝对精度，位置阶段只相信"此刻"的快照值而不是历史积分。

## 那为什么高度不能像 Yaw 一样写？

现在针对你实际用的 **TOF 激光**来回答，理由和气压计不同但又更直接：

### Yaw 的传感器：陀螺仪测量的是"自身的旋转"

```
陀螺仪 → 角速率（无论你在哪、下面是什么地面，数据都一样）
         → 积分 → 角度（纯自身状态，不受外界影响）
```

### 高度的传感器：TOF 激光测量的是"离地面的距离"

```
TOF 激光 → 地面距离（地面是平的 → 准；飞过桌子 → 突然跳变）
         → "高度"会因地面变化而变，但这不是飞机真的在动
```

把油门杆映射为"高度速率"并积分进高度目标：

```c
Desired_height += stick * CLIMB_RATE * dt;  // 模仿 yaw
```

**在平地上**：激光测距是干净的、不漂移的，这个方案理论上可行，甚至可能比现在的"速度+快照"更好——因为积分平滑、没有模式切换冲击。

**一旦地面不平**：飞机飞过一张桌子 → 激光测距从 80cm 骤降到 30cm → `state->height` 跳变 → PID 看到 50cm 的"误差"（实际是地面变了不是飞机动了）→ 猛推油门 → 飞机窜上天。

这不是 PID 参数能解决的问题，是物理传感器本质决定的。

### 对比一下

| | 陀螺仪 (Yaw) | TOF 激光 (你的高度) | 气压计 |
|---|---|---|---|
| 测量什么 | 自身角速率 | 离地距离 | 绝对大气压 |
| 受地面影响 | ❌ 不受 | ✅ 受地形影响 | ❌ 不受 |
| 噪声 | 低 | 低 | 高（±10~30cm） |
| 漂移 | 短期可忽略 | 无漂移（测量绝对距离） | 温漂、气压漂 |
| 适合积分型控制 | ✅ 完美 | ⚠️ 平地可以，有障碍物不行 | ❌ 积分噪声发散 |

> TOF 激光测的是"离地面的距离"，不是"飞行高度"。地面不平，高度就乱跳。Yaw 的陀螺仪测的是自身旋转，跟外界无关。这就是为什么高度不能照搬 yaw 的积分模式——传感器量的是不同的东西。气压计不受地面影响但噪声大漂移多，TOF 干净但受地形影响，**垂直方向上没有一个既绝对、又干净、又不受外界干扰的传感器**。

2. **速度环 Kp 太弱，积分一家独大** —— 积分天然滞后，滞后 + 主导 = 振荡。MiniFly 的 Kp 大到压住了积分
3. **高度位置环 DeadBand=0** —— 连 1-2mm 的 TOF 噪声都在驱动修正，Yaw 有 0.1° 死区挡着
